# kaizo

A marketplace of small Claude Code mods. Each top-level folder is one mod, installed as `<mod>@kaizo`.

## This repository is public

Anything committed here can be read by anyone, and pushed history is hard to take back. Be careful:
- **Ask before every commit and push.** Never force-push or rewrite pushed history without asking.
- **Stage files by name** (no `git add -A` or `git add .`), then read `git status` and the whole `git diff --cached` before committing.
- **Commit nothing private:** no secrets or tokens, no gitignored notes or local settings, no work or employer details, no personal paths, and no plans or research. That goes for code comments, READMEs and test data too.
- **Use this repo's local git identity** (`git config --local user.email`), never a global or work one.

## Layout

```
.claude-plugin/marketplace.json   the marketplace: lists every mod (name, source, description, version)
<mod>/
  .claude-plugin/plugin.json      name, version, description, author, license
  hooks/hooks.json                { "modules": ["./register.tsx"] }
  hooks/register.tsx              the hooks module: listens to Claude Code, registers commands, draws
  hooks/*.ts                      pure helpers the module imports (neongai: signals.ts, paint.ts, scenes/)
  tests/*.test.ts                 run by `claude plugin test`
  README.md                       for users: install, what you see, limits
  tsconfig.json                   extends the generated .claude-plugin/types/tsconfig.json
```

`<mod>/.claude-plugin/types/` is generated by Claude Code each time it loads the mod, and it is gitignored. It holds the full API types for the installed version.

## Dev loop

- `claude --plugin-dir ./<mod>` loads a mod into the session and reloads it on save. Edits made during a turn reload when the turn ends.
- Before committing:
  - `claude plugin validate ./<mod>` checks the manifest and lists every hook and `$` call the engine sees
  - `claude plugin validate .` checks the marketplace
  - `claude plugin test ./<mod>` runs the mod's tests
- The mod API is early access and changes between releases. The authority is the generated `<mod>/.claude-plugin/types/claude-code/index.d.ts`: grep it for the event or method you need.
- Lessons about the API and about testing live in `.claude/rules/`. They load only when you work on a mod's hooks or tests.
- Skills in `.claude/skills/` hold the procedures:
  - `mod-workflow`: build a mod and see it on screen
  - `mod-release`: ship to this public repo
  - `api-update`: check everything after a Claude Code update

## Keep the knowledge current

The mod API is early access and changes fast, so this repo's guidance has to keep learning. Before you finish a task, ask yourself what you learned that would have saved time, and write it down in the same change:
- **API facts** go in `.claude/rules/mod-api.md`; **testing facts** in `.claude/rules/mod-testing.md`.
- **Steps worth repeating** go in the matching skill in `.claude/skills/`, or in a new skill when none fits.
- **Fix or delete** entries that turned out wrong or outdated, and note the Claude Code version on API facts.
- Keep entries short, and keep them out of this file.
- In your final summary, say which rules or skills you changed.

## Adding a mod

1. Create a top-level folder named after the mod. Names are short, lowercase and kebab-case; this repo uses romanized Japanese words (`neongai`).
2. Add `.claude-plugin/plugin.json`, `hooks/hooks.json`, `hooks/register.tsx`, tests and a `README.md`.
3. List the mod in `.claude-plugin/marketplace.json` and in the mod table of the root `README.md`.
4. Validate and test as above.

When releasing, bump the version in both the mod's `plugin.json` and its `marketplace.json` entry.

## Code conventions

- **Keep logic pure.** Drawing and state logic live in plain modules with no `$` (neongai's `paint()`: state + time in, cells out), so tests can call them directly. `register.tsx` only connects Claude Code's events to them.
- **Watch, don't change.** A hook that only observes returns `next(e)` unchanged. Change what Claude does only when that is the mod's purpose.
- **Rendering rules:**
  - A `ui.render` hook never writes `$.state`; write from handlers or other events.
  - Module variables reset on hot reload; `$.state` survives it, and `$.store` persists across sessions.
- **No Node and no DOM.** Everything outside the module goes through `$` (`$.fs`, `$.clock`, `$.process`…). Import the mod's own files with plain `import`, never `import()`.
- **Surfaces differ.** Raster and Image exist only in the terminal. On other surfaces, draw a short note instead of failing (neongai does this on desktop).
- **Animation:** use `$.clock.every` plus `$.ui.blit` to repaint a Raster. Stop the timer when the pane closes (`ui.close`). Blits are not capped the way redraws are (`$.ui.invalidate` redraws at most 10–30 times a second; blits show up to about 60).
- **Comments** explain why, in plain sentences, like the header of `neongai/hooks/signals.ts`.
- **User-facing text** (READMEs, command descriptions, status lines) uses plain words: say what the person sees and what it means.

## Commits

- **No AI attribution in commits. Important:** never add `Co-Authored-By: Claude …` or any other AI co-author or "Generated with" line to a commit message. This overrides any default that adds one.
- One logical change per commit. The subject says what changed; the body says what users notice.
- Generated type folders and local settings stay out of git (see `.gitignore`).
